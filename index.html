01 — Context

The Problem with SAP + AI Today

SAP systems hold your most critical business intelligence — but accessing it requires trained operators, complex transactions, or expensive custom modules. AI models can change this, but only if given a structured, secure channel to SAP data.

🔒

SAP Data Is Siloed

Purchase orders, inventory levels, vendor master data, cost center reports — all trapped behind T-codes, role-based access, and complex UI flows. Non-SAP users have zero self-service path.

⏱️

Every Query Needs an SAP Expert

A manager wanting to check vendor status or pending approvals must either log into SAP themselves or raise a request to the SAP team — creating bottlenecks across every department.

💸

Custom AI Integration Is Expensive

Each SAP module requires bespoke integration work. There's no standard AI interface. SAP's own Joule AI is licensed, complex, and locked to their ecosystem — not suitable for flexible AI workflows.

🚀

MCP Is the Universal SAP-AI Bridge

Model Context Protocol provides one standardised interface. Build the MCP server once, and any MCP-compatible AI — Claude, GPT, Gemini, or a private model — can query and act on SAP data immediately.

02 — SAP Integration Methods

How the Adapter Talks to SAP

The ERP Adapter layer supports multiple SAP communication protocols. Each method has different use cases, performance characteristics, and setup complexity. The prototype uses mock data; production uses the real adapters below.

SAP RFC / BAPI RECOMMENDED

Remote Function Call is SAP's native integration protocol. BAPI (Business API) functions are stable, documented RFC wrappers designed for external consumption. The node-rfc library provides Node.js bindings to SAP's NWRFC SDK.

  • Direct access to any SAP function module
  • Best performance — native SAP protocol
  • Used for: MM, SD, FI, CO, PM, WM operations
  • Requires SAP NWRFC SDK + RFC credentials
  • Example: BAPI_PO_GETDETAIL for PO details

SAP OData / REST API MODERN

SAP Gateway exposes business data as OData v2/v4 services over HTTP. S/4HANA provides extensive OData APIs out of the box. This is the recommended approach for cloud/hybrid SAP deployments.

  • Standard HTTP — works with any HTTP client
  • Rich filtering, sorting, and $expand support
  • Used for: S/4HANA Cloud, newer deployments
  • Requires SAP Gateway activation and user auth
  • Example: /sap/opu/odata/sap/MM_PUR_PO_MAINT_V2_SRV

SAP IDocs / ALE LEGACY

Intermediate Documents for asynchronous message-based integration. Suitable for batch operations and system-to-system replication. Lower priority for real-time AI queries but useful for event-driven triggers.

  • Asynchronous — not suited for real-time queries
  • Good for event triggers (new PO created → AI notified)
  • Existing infrastructure likely already in place

Mock ERP Adapter PROTOTYPE

For the demonstration phase, the adapter runs against a realistic mock data layer with 50+ seeded SAP-style records. This proves the entire MCP communication pattern without requiring live SAP credentials.

  • Zero SAP setup needed for demo
  • Same interface as live adapters — swap in production
  • Seeded with realistic MM, SD, FI, and WF data
  • Supports all filtering, status codes, and relations

02 — Component Breakdown

Internal Server Components

Server Entry Point
Bootstraps transport (stdio/SSE), registers capabilities, initialises middleware chain. Handles the MCP initialize handshake and sends serverInfo with supported protocol version.
Tool Registry
Central manifest of all tools with their JSON Schema input definitions, descriptions, and handler references. The AI uses descriptions for tool selection — these must be precise and business-language-friendly. Adding a new tool is a single registry entry.
Request Router
Receives tools/call requests, validates input against the registered schema using Zod, resolves the handler function, executes, and formats the CallToolResult response with typed content blocks.
Auth Middleware
API key validation for local deployments; JWT/OAuth2 token verification for remote SSE deployments. Supports per-tool permission scopes — e.g. approve_workflow_item requires elevated sap:write scope.
Rate Limiter
Sliding window rate limiting per user and per tool. Prevents runaway AI agents from flooding SAP with requests. Configurable per environment — generous in dev, strict in production.
Audit Logger
Append-only structured log of every tool call: timestamp, user, tool name, input parameters (sanitised), response summary, and duration. Written to file and optionally streamed to a logging service. Critical for enterprise compliance.
ERP Adapter Interface
TypeScript abstract class defining all ERP operations. Both MockERPAdapter and LiveRFCAdapter implement this interface. Tool handlers call the adapter methods — they never know which adapter is active. Swap adapters via environment config.
Response Formatter
Converts raw ERP data structures to MCP TextContent or JSONContent blocks. Handles pagination, truncation, and error wrapping. Formats numbers, dates, and currency to be AI-readable and human-friendly.
03 — Security Model

Security by Design

Every AI-triggered SAP action passes through multiple security layers before execution. No tool call reaches SAP without validation, authentication, and logging.

🔑
Authentication

API key for local stdio. OAuth 2.0 client credentials flow for remote SSE. Separate service account per environment with minimal SAP authorisation profile.

🛡️
Input Validation

Every tool input validated against Zod schema before touching any SAP adapter. Injection-safe — no raw string concatenation into SAP function parameters.

🔒
Permission Scopes

Read-only tools vs write-action tools have separate permission scopes. Approval tools require explicit sap:approve scope. Principle of least privilege enforced per deployment.

📋
Audit Trail

Immutable append-only log of every AI-triggered action with full parameter capture. Every SAP write action is confirmed before execution and logged after. Full reversal path documented.

⚡
Rate Limiting

Per-user and per-tool rate limiting prevents runaway agentic loops from overloading SAP. Separate limits for read vs write operations. Circuit breaker pattern for SAP connection faults.

🌐
Network Isolation

MCP server deployed on internal network — same segment as SAP. No SAP credentials ever leave the perimeter. External AI APIs only see the MCP protocol layer, never raw SAP data schemas.
